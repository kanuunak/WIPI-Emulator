## 2. 이번에 확립된 결정·절차

- **rust/ 승인 예외**(AGENTS.md 규칙 1): session.rs tick 1ms(발열) / wie를 `kanuunak/wie` 포크로 교체 + 수정 2건. 코어 수정 절차:
  `kanuunak/wie`에 `fix/…` 브랜치(기존 브랜치 위에 쌓음) → `cargo test -p <크레이트>`·clippy → headless로 해당 게임·데모 2종 → `rust/Cargo.toml` rev 교체 → `cargo metadata`로 Cargo.lock의 wie 출처 줄만 갱신(lock 재생성 금지). 현재 브랜치 `fix/ktf-storage-access-level` @ d45b8a7c(= 38f7e04f + d9675f5f + d45b8a7c). Claude GitHub 앱이 `kanuunak/wie`에도 설치돼 있어 세션에서 push 가능.
- **복제 방지(DRM) 인증은 우회하지 않는다**(이노티아 연대기2 인증오류 1001 — `p/cert.c2s`). 에뮬 호환성 문제만 고친다.
- **배치 우선순위**: 배치 편집으로 저장한 배치(`customLayout.<가용W>x<H>`) > 설정(자동/위아래/좌우). 화면이 저장 때의 85% 이상이면 비율대로 줄여 씀.
- **폴더 임포트 원칙**: 그 폴더를 zip으로 묶어 임포트한 것과 같게. jar 단독은 표시 파일이 하나도 없을 때만.
- 배속: 사용자 결정 "측정 후" → 측정 결과 무거운 게임은 `wie-emulator`가 코어 하나를 거의 다 씀(79~99%) → 배속해도 안 빨라짐. 보류. 가벼운 게임에만 효과(필요하면 `MobilePlatform::now` 배율 + JNI 1개, 규칙 1·2 예외 필요).
- 멀티코어: CPU 흉내는 한 코어가 원칙(옛 폰 = 단일 코어). 성능은 프로파일링으로 핫스팟을 찾아 최적화하는 길만 남음(무거운 게임 파일 필요).

## 4. 알려진 한계·후보

- 무거운 게임에서 에뮬 스레드가 코어 하나를 거의 다 씀 → 성능 프로파일링(게임 파일 필요), 배속은 그 뒤.
- LGT·SKT 게임은 코어 메타데이터가 이름을 못 뽑아 폴더/파일 이름으로 표시.
- rust 변경안(승인 전): `session::stop()`이 SESSION 락을 쥔 채 join — tick이 안 돌아오는 게임이 나오면 락 밖 join + 타임아웃(HANDOFF_Phase3 §5).
- 남은 STUBS(동작에 영향 없었음): `MC_knlUnsetTimer`, `MC_mdaClipSetVolume`/`GetVolume`, `MC_knlGetAccessLevel`(0 반환 스텁).
- **배포 전 필수**: 오픈소스 고지 자동 생성(명세 §4.2 P1 — Rust `cargo about`, Android AndroidX/Compose/Kotlin). 판매·배포 시 게임 파일 동봉 금지, 원작자(wie MIT) 고지 유지.
